# Skill: Test Generation## TriggerDeveloper or QA needs tests generated for a feature, endpoint, or component.## Pre-conditions- Project stack and commands defined in `.tai/config/project.yaml`- Test patterns documented in `.tai/context/patterns.md` (file naming, structure, assertion style)- Sprint ISC criteria exist in `.tai/context/sprint-current.md`- The feature to be tested is implemented or its spec is available## Steps1. Read `.tai/context/sprint-current.md` to identify the ISC criteria relevant to this feature.2. Read `.tai/context/patterns.md` to identify test conventions (file naming, directory, test structure, assertion library).3. Read the feature code or spec to understand its inputs, outputs, and behavior.4. Generate happy path tests: valid inputs produce expected outputs for each ISC criterion.5. Generate failure mode tests:   - Invalid input (wrong types, missing required fields)   - Auth rejection (unauthenticated, wrong role)   - Network or dependency errors (if applicable)6. Generate boundary case tests:   - Empty values (empty string, empty array, null)   - Maximum length values   - Special characters and encoding edge cases7. Generate role-based scenario tests: verify correct behavior for each role that should and should not have access.8. Run all generated tests using the command from `.tai/config/project.yaml` → `commands.test`.9. Fix any tests that fail due to test bugs (not feature bugs). Report feature bugs to the developer.10. Log skill completion to `.tai/telemetry/sessions.jsonl`.## Verification Gate- [ ] Happy path tests cover each relevant ISC criterion- [ ] Failure mode tests exist (invalid input, auth rejection)- [ ] Boundary case tests exist (empty, max length, special characters)- [ ] Role-based scenario tests cover authorized and unauthorized access- [ ] All tests pass
