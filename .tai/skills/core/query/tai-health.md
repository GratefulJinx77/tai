# Skill: /tai-health## TriggerUser runs `/tai-health` to view project health metrics.## Pre-conditions- Telemetry files exist at `.tai/telemetry/hooks.jsonl` and `.tai/telemetry/boundaries.jsonl`## Steps3. Read `.tai/telemetry/hooks.jsonl`.4. Read `.tai/telemetry/boundaries.jsonl`.5. Aggregate hook events:   - Count total hook executions.   - Count by result: `pass`, `fail`, `bypass`.   - Compute pass rate: `pass / total * 100`.   - Compute failure rate: `fail / total * 100`.   - Break down failures by check type from `details.failures[]`.6. Aggregate boundary events:   - Count total violations.   - Count violations in the last 7 days.   - Identify most-violated rules.7. Compute trends (compare last 7 days vs prior 7 days):   - Hook pass rate trend (improving / stable / declining).   - Violation rate trend.8. Format output as health dashboard.9. Refresh the status line.## Output Format```═══ TAI Health Dashboard ═══════════════════════Hook Execution Summary (all time):  Total runs:    45  Pass:          41 (91.1%)  Fail:           3 (6.7%)  Bypass:         1 (2.2%)Failure Breakdown:  tsc:       2 failures  eslint:    1 failureBoundary Violations:  Total:         2  Last 7 days:   1  Top rule:      src/services/extraction/** → src/services/pricing/**Trends (last 7 days vs prior 7 days):  Hook pass rate:     93% → 89% (declining)  Violations:         1 → 1 (stable)```### Empty State```═══ TAI Health Dashboard ═══════════════════════No telemetry data yet. Health metrics will appear after hooks run and telemetry accumulates.```## Telemetry Fields Read- `hooks.jsonl`: `timestamp`, `event`, `result`, `details.checks_run`, `details.failures`, `details.duration_ms`- `boundaries.jsonl`: `timestamp`, `event`, `details.rule`, `details.action`## Privacy- All team members can view this data.
