# Custom SkillsThis directory is for team-created custom skills. Skills placed here are automatically discoverable by TAI.## Creating a Custom Skill### File StructureEvery skill needs at minimum a `SKILL.md` entry point:```custom/└── my-skill/    ├── SKILL.md           # Required: Entry point with frontmatter + routing    ├── Workflows/         # Optional: Workflow definitions    │   ├── Default.md    │   └── Advanced.md    ├── Templates/         # Optional: Output templates    ├── Tools/             # Optional: TypeScript/Python tooling    └── Data/              # Optional: Static data files```### SKILL.md Format```markdown---name: MySkilldescription: What the skill does. USE WHEN trigger phrase 1, trigger phrase 2, trigger phrase 3.---# MySkillBrief description of what this skill does and when to use it.## Workflow Routing| Request Pattern | Route To ||---|---|| Default action, standard use | `Workflows/Default.md` || Advanced mode, deep analysis | `Workflows/Advanced.md` |```The `---` frontmatter block is required. The `name` field identifies the skill. The `description` field includes `USE WHEN` trigger phrases that tell TAI when to invoke this skill.### Workflow File Format```markdown# Workflow: Default## TriggerWhen the user requests [action].## Steps1. Read relevant context from `.tai/context/`.2. Perform the analysis or action.3. Format output according to the template.4. Log completion to `.tai/telemetry/sessions.jsonl`.## Output Format[Define the expected output structure]## Verification Gate- [ ] Step 1 completed successfully- [ ] Output matches expected format```### Registering in packages.yamlAdd your custom skill to `.tai/packages.yaml`:```yamlskills:  my-skill:    version: "1.0.0"    tier: optional    description: "What the skill does"```### Tier Levels- **required** - Loaded every session, core functionality- **recommended** - Loaded by default, can be disabled- **optional** - Only loaded when explicitly invoked### Example: Deploy Verification Skill```custom/└── deploy-verify/    ├── SKILL.md    └── Workflows/        └── Verify.md````SKILL.md`:```markdown---name: DeployVerifydescription: Post-deployment verification. USE WHEN deploy verify, check deployment, verify deploy, post-deploy check.---# DeployVerifyRuns post-deployment verification checks against the live environment.## Workflow Routing| Request Pattern | Route To ||---|---|| Deploy verify, check deployment, post-deploy | `Workflows/Verify.md` |````Workflows/Verify.md`:```markdown# Workflow: Verify## Steps1. Read deployment target from `.tai/config/project.yaml` -> `deploy.url`.2. Run health check against the deployed URL.3. Verify version endpoint returns expected version.4. Run smoke tests against live endpoints.5. Report results.## Verification Gate- [ ] Health endpoint returns 200- [ ] Version matches expected release- [ ] Smoke tests pass```
